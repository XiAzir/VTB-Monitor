# 原界面 / 原 TypeScript Pi 桥接审查

## 本轮已处理

原始 `.svelte` 与 CSS 保持不变；不仅使用类似样式，而是运行原 SvelteKit 页面和原服务端表单。`getPiStatus` 和历史查询拆到轻量模块，普通后台页面不会为查询状态而主动加载整个 Pi provider 图。

Rust 是唯一作业租约持有者，TypeScript 只执行给定 Pi 工作，不再启动自身 scheduler。新增动态的逐条 Rust 作业在跨入 TypeScript 前对比原 `pi_dynamic_analysis_versions`，避免一次基线已消费多条动态后继续重复基线；编辑走原 revision 表和工具，不提前撤销其全部事件。原周表候选、确认界面与固定日程顺延路径保留。

控制接口不是公网 API：私有端口只绑定127.0.0.1，随机能力令牌不放在响应、日志或 URL。Rust移除外部伪造的管理与能力头；public/management请求在Rust侧选择独立命名空间；检查URL归一化之后的路径，拒绝dot-segment越界与反斜杠。响应保留多个Set-Cookie、Location以及Pi流式body，不把流式响应全读完再转发。变更请求不自动重试。

辅助进程启动加锁、读有界握手、父管道关闭退出、kill_on_drop；响应流直到EOF都持有活动租约，避免空闲回收杀掉正在流式回复的Pi。用户取消控制请求时停止辅助进程，避免过期任务继续写库；模型工作之间还有Rust全局昂贵操作限制与TypeScript busy检查。

图片只规划元数据再逐批加载；读前检查大小，缺图等待或失败。新消息保存图片引用说明而非base64二进制，旧图仍在媒体归档。没有通过删除归档、关闭Pi或只计算父进程内存来满足预算。

## 必须继续注意

这是同一主机的混合程序，不是远程不可信插件沙箱。具备服务用户权限的本地进程仍可访问其配置或内存。不要公开Node私有端口、不要运行第二个同库调度器、不要改用新主密钥去解密旧数据库。

原Pi的语义和工具保留，不代表其全部原有边界缺陷已消失。真实平台、多供应商、长时间生产数据还没有被本地确定性模拟替代。100–150MiB指标必须对应完整混合负载、工作完成率与OOM检查，而不是原生Rust旧实验结果。

依赖审计原项目发现nodemailer锁定版本存在高危公告。功能回归流水线会保存独立的dependency-audit.json；它不以审计失败掩盖功能测试，也不能把功能流水线通过当成依赖审计通过。部署前需要将该依赖与lockfile一起更新到供应商修复版本并复测。
