# 原 WebUI / TypeScript Pi 集成审查

## 已落实的检查

原8个Svelte页面/组件与原CSS未重写，CI比较基线cdb62d9，运行原浏览器流程及桌面/移动端截图。原服务端表单、增强表单协商、会话Cookie、Location、管理端权限和Pi历史接口仍运行原代码。

Rust唯一持有作业租约；TypeScript辅助进程不启动scheduler。逐条Rust新增任务进入Pi前检查原已分析内容版本，避免基线已处理多条后重复调用。编辑创建原pi_revision_analyses并交给原工具判断，不先行抹掉事件。原周表候选及固定安排到期投影恢复。

私有能力令牌只在父子进程内使用；公网请求不能提供管理监听标记。按public/management分开命名空间，检查URL归一化后路径，拒绝dot-segment与反斜杠越界。去掉hop-by-hop和Connection指定头，保留Set-Cookie、重定向和Pi流。变更请求不自动重试。

启动加锁、有界握手、父管道EOF退出、kill_on_drop；活跃响应持有租约直到EOF。相对数据路径在父进程解析成绝对路径，避免自定义工作目录打开另一份数据库。SDK额外stdout被有界排空，不阻塞管道。控制请求取消会终止辅助进程，防止失去租约的任务继续写入。

图片读前检查，元数据规划后逐批读取，缺图不提交半份结果。新消息不重复存图像base64。内存测试计算整个Rust+Node组，不删除图片、关闭Pi或只统计父进程来获得漂亮数字。

## 大图片回归中的实际修正

原Pi周表提交工具成功后会再次携带原图调用模型生成结束语，造成额外token与内存峰值。现在使用原SDK的shouldStopAfterTurn：仅周表/编辑分析，结构化提交完成且本轮全部工具成功后终止；不在第一个工具中直接abort。正常聊天/主播分析仍保留多轮；4项SDK回归涵盖多工具、空提交、失败修复和正常多轮。

Nodemailer已从9.0.5更新至同主版本9.1.1，并同步package-lock；生产依赖audit恢复通过。Rust依赖已写入Cargo.lock。临时写仓库的修补流水线从交付分支移除，最终回归流水线只有contents:read权限。

## 未作出的保证

这是同一服务用户下的本地辅助进程，不是不可信插件沙箱；具备服务用户权限的程序仍能访问其配置。不能公开私有端口、并行启动第二套同库调度器或更换解密主密钥。

保留原Pi不等于修复其全部既有时间语义/证据边界。测试供应商为确定性模拟，未验证真实模型准确率、所有网关、每种动态或长期运行。9MiB合成图片测试只验证载荷与工具流，不能替代图像内容正确性评估。

150MiB通过只对应同次提交的有限测试场景，不能承诺100MiB硬限额、无限并发、大数据库和所有超长模型任务都不失败。冷启动和有界排队会影响延迟；繁忙请求会503/Retry-After。上线前使用数据库/媒体副本，保留原版本回滚通道。

## 续审收尾

前一轮提交 `6cf4f3b` 的六次集成消融均通过；主动 GC 开启组峰值中位数 115.8164 MiB，关闭组 114.0117 MiB，未证明主动 GC 有收益。因此默认关闭，仅 `VTBM_REQUEST_GC=1` 显式启用；后续报告改用 `default` / `with_request_boundary_gc`，避免将开启组预先命名为“优化组”。这些数字只描述前一轮，不冒充当前提交实测。

补上公网请求体的 15 秒读取截止时间，避免慢上传无限占用 API 许可；512 KiB 上限保持不变。逐一处理所有 Connection 头中列出的 hop-by-hop 字段，同时保留多个 Set-Cookie 和 Location。增加请求体超限、原表单字节不变、停滞流截止和多值头回归测试。

服务模板改用独立 hybrid 环境文件，给出与写入白名单一致的数据目录、数据库和媒体默认位置，并设置私有 StateDirectory/UMask。混合程序真实入口及环境文件以 rust/README.md 为准；根 README 仍描述旧 Node 回退模式。增加原后台管理页桌面／移动端截图与原 Pi 配置入口可见性检查；所有 Svelte/CSS 仍不修改。截图用于人工审阅，不声称已经做像素级基准差分。

交付源码须与最终 CI 的 tested-source-commit.txt 一致；测试产物在代码之外单独归档。通过 npm audit 只表示当次已知生产依赖公告检查，不等于完整安全证明。真实 B 站和付费供应商、复杂超长图文、原有时间语义边界与长期稳定性仍保留上文限制。
