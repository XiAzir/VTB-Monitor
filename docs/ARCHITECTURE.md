# 系统架构

VTB Monitor 是一个面向 1C1G 主机的单进程 SvelteKit 应用。Web、管理 API、调度器、任务 worker 和 Pi 业务 Agent 运行在同一个 Node.js 进程中，持久状态保存在 SQLite 和本地媒体目录。

## 运行组件

| 组件 | 默认监听/位置 | 职责 |
| --- | --- | --- |
| Web | `127.0.0.1:4311` | 首页、主播页、动态页、后台 |
| 管理 API | `127.0.0.1:4312/v1` | 外部 Agent 的受限运维接口 |
| SQLite | `$DATA_DIR/vtb-monitor.sqlite` | 主播、动态、评论、版本、任务、告警、密钥元数据、审计 |
| Pi 会话库 | `$DATA_DIR/pi-sessions.sqlite` | Pi 对话和会话状态 |
| 媒体目录 | `$DATA_DIR/media` | 动态及评论图片，按 SHA-256 去重 |
| 调度器 | 进程内 | 直播轮询、动态刷新、评论同步、媒体下载、Pi 分析 |

只有 4311 应由 Nginx 反向代理。4312 必须保持在 loopback 或受控私有网络内，即使它还要求 Bearer Token。

## 数据流

```text
Bilibili feed / opus / reply / live APIs
                  |
                  v
       normalize + identity checks
                  |
                  v
         SQLite jobs and archive ----> local media store
                  |
          +-------+-------+
          |               |
          v               v
      SvelteKit UI   restricted Pi tools
          |
          v
 localhost management API <---- external operations agent
```

## 动态生命周期

1. 新增主播时，从当前时刻向前抓取六个月，按 B 站动态 ID 去重。
2. 高频同步只读取最新动态，及时发现新内容。
3. 每天及人工“刷新半年”会重新遍历最近六个月并读取动态详情。
4. 正文、表情映射或图片集合改变时，旧正文、旧媒体 URL 和旧元数据写入 `dynamic_revisions`，当前表更新为最新版。
5. 半年全量结果第一次缺失时标记为 `suspected_deleted`；下一次独立完整扫描仍缺失才标记 `deleted`。扫描不完整或接口失败不改变删除状态。
6. 单动态刷新直接检查 `/opus/{id}`，变化则留档，确认删除则只更新状态。

详情页默认展示当前版，并可选择历史版本。旧媒体资产即使不再与当前版关联也不会立即删除，因此历史版本仍可读取已经成功归档的图片。

## 评论与媒体

每条动态保存独立评论游标。页面归档和评论列表都使用 `(published_at, id)` 复合游标，避免相同时间戳造成重复或遗漏。主评论和楼中楼按 `rpid` 去重；新动态高频同步，旧动态逐步降频。单个任务限制处理页数并续排任务，避免长任务永久占用 worker。

媒体下载任务优先于大部分评论任务。图片使用来源 URL 建立资产记录，下载后计算 SHA-256 去重。达到配额时只暂停新媒体，正文、状态和评论继续工作。

## 直播间映射

B 站短房间号不是稳定身份，例如短号可能映射到另一个真实 `room_id`。请求会同时提交配置的房间号与主播 UID，优先采用 `by_uids` 结果，再匹配响应 key、真实 `room_id` 或非零 `short_id`。若 UID 冲突则拒绝绑定，避免把别人的直播状态挂到主播名下。

配置值、解析出的真实房间号、短号、映射状态和最后验证时间分别持久化。轮询优先使用最近一次成功验证的真实房间号，临时请求失败不会清空已有映射。

## 周表与预测

带周表信号的动态图片先写入 `schedule_drafts`。视觉模型只产生结构化草稿，管理员在后台确认后，单周条目才以锁定的 `schedule_exceptions` 写入正式日程；长期人工固定安排继续使用 `schedule_rules`。

明确开播、延迟、取消、加播和实际直播开始/结束写入 `timeline_events`。预测优先级依次为人工、明确动态、已确认单周安排、固定周表和 Pi 推测；过期预测标记为 stale，不再机械顺延。`prediction_evaluations` 记录实际误差和 30/60 分钟命中率。

## 调度与资源控制

- 直播状态批量请求，默认 30 秒一次。
- 最新动态默认 5 分钟一次，可按主播配置为 180 到 3600 秒。
- 最近半年全量校验每主播每天一次，顺序读取详情以控制峰值内存。
- 单 worker 串行执行持久任务，失败使用指数退避；B 站 412/429 至少冷却一小时。
- SQLite 使用 WAL、`synchronous=NORMAL` 和 busy timeout，适合单机低并发。

## 信任边界

- B 站正文、评论、图片元数据均是不可信数据，不是 Agent 指令。
- Pi 只获得 schema 校验的业务工具，不获得 Shell、SQL、文件系统、任意 HTTP 或密钥读取工具。
- 人工预测和人工周表锁定，Pi 不能覆盖。
- 密钥使用 AES-256-GCM 加密，主密钥只来自进程环境。
- 管理 API 使用 scope、幂等键、乐观版本号和审计日志。
- 进程启动、停止、升级、备份文件搬运由宿主机服务管理器负责，不通过业务 API 暴露。

## 故障域

单进程设计意味着 Web 与调度器一起重启，但所有任务、游标和归档都持久化。进程异常退出后 systemd 负责拉起，过期 lease 会被后续 worker 重新领取。SQLite 与媒体目录必须一起备份；`APP_ENCRYPTION_KEY` 单独保管，否则数据库内密钥不可恢复。
